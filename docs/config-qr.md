# Передача VPN-конфигурации через QR

## Где находится кнопка

- **TrustTunnel / R-TrustTunnel:** «Ключи и устройства» → «QR-код» рядом с действующим ключом. У отозванных ключей кнопки нет.
- **Hysteria:** «Пользователи» → строка пользователя Hysteria → «QR-код».

Нажатие открывает предупреждение. Конфигурация запрашивается только после
подтверждения «Показать QR-код». Отсканируйте изображение в клиенте с поддержкой
соответствующего протокола. Обычная камера телефона не обязательно умеет
импортировать VPN-профили.

В окне экспорта есть переключатель «QR-код / Ссылка», копирование ссылки,
скачивание исходной конфигурации и сохранение QR в SVG с белым фоном.
Прежняя кнопка «Показать / скачать» также открывает это окно, но сначала
показывает текст ссылки. При запрете доступа к буферу обмена ссылка выделяется
для ручного копирования.

## Формат и ограничения

QR кодирует **точное содержимое существующего экспорта**: результат `codec(...,
"tt")` для TrustTunnel либо URI, возвращённый агентом Hysteria. Ключ не
перевыпускается; параметры TLS, сертификат, obfs и остальные поля не удаляются.
QR не является отдельной конфигурацией маршрутов и не изменяет VPN-службы.

Если профиль не помещается в один QR, окно показывает причину и оставляет
доступными копирование и скачивание полного профиля. Конфигурация не обрезается,
сертификат не удаляется, проверка TLS не отключается ради уменьшения размера.
SVG содержит геометрию чёрно-белого QR и белое поле в четыре модуля; зависимости
Pillow и внешние сервисы генерации не требуются. Используется уже имеющийся
в базовом образе пакет `qrcode`.

## Доступ и приватность

Существующий `POST /console/api/export` принимает дополнительный необязательный
параметр `qr: true`. Сохраняются проверки администратора, CSRF, Origin и явного
`consent: true`. ID должен быть положительным целым числом. Без `qr` формат
старого ответа не меняется.

При запросе QR ответ содержит `qr_data_url` и `qr_error`. Генерация выполняется
в рабочем потоке, локально в консоли, из уже полученного профиля. Секреты не
передаются в URL, сторонние QR-сервисы, очередь заданий или аудит. Ответ имеет
`Cache-Control: no-store`; в аудит пишется только существующее событие
`key.export` с протоколом и ID.

Закрытие окна убирает секрет и QR из DOM и освобождает временные URL скачивания.
Запоздавший ответ не отображается в закрытом или новом окне. Это не удаляет
уже скачанный файл, сделанный снимок экрана или вручную скопированный буфер.
QR нужно защищать так же, как пароль подключения.

## Обновление и проверка

Исправление затрагивает только консоль. Включите его в используемую ветку
развёртывания, сохранив остальные установленные изменения, затем пересоберите
консоль по [инструкции установки](../deploy/README.md). Смена маршрутов и
перевыпуск ключей для появления кнопки не нужны.

Изолированные проверки:

```sh
python -m pip install 'qrcode==8.2' pytest fastapi httpx Jinja2 cairosvg opencv-python-headless playwright
python -m playwright install --with-deps chromium
python -m pytest -q server/tests/test_config_qr.py server/tests/test_config_qr_browser.py
```

Тесты используют настоящий API экспорта, шаблон, JS/CSS и генератор QR, но
изолированные учётные записи и заменённые границы агента/кодека. QR считывается
обратно и сравнивается с исходным содержимым. Проверяются оба протокола,
подтверждение, старый API без QR, отозванный ключ, ошибки, слишком длинный
профиль, повторный клик, запоздавший ответ, копирование, скачивание и мобильная
раскладка. Скриншоты CI содержат только вымышленные тестовые данные.

Это не проверка подключения реального VPN-клиента к рабочему серверу.
