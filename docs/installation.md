# Гайд по установке Tunnel

Инструкция сверена с кодом установщика 26 октября 2026 года. Для нового сервера
мастер сначала разворачивает портал, единую консоль и агент. VPN-протоколы
устанавливаются отдельно из консоли. Для существующего сервера используется
[установка sidecar](../deploy/README.md), а не мастер с нуля.

## 1. Выберите сценарий

| Сценарий | Что использовать |
|---|---|
| Пустая Ubuntu 24.04 x86_64 | `tunnel-installer-ubuntu24-amd64.run`, [инструкция Ubuntu](fresh-install.md) |
| Пустая CentOS Stream 9/10 x86_64 | `tunnel-installer-centos-stream-amd64.run`, [инструкция CentOS](fresh-install-centos.md) |
| Уже работает портал TrustTunnel | [Установка консоли на существующий сервер](../deploy/README.md) |
| Восстановление данных или обновление рабочего сервера | [Эксплуатация и восстановление](operations.md) |

Мастер требует systemd, root/sudo, минимум 2 CPU, 4 ГБ RAM и 15 ГБ свободного
места. Для первой сборки на 4 ГБ RAM желательно 2 ГБ swap. CentOS Stream 10
требует x86-64-v3. ARM, CentOS Linux 7/8 и Stream 8 не поддерживаются.
Обычный Docker-контейнер без systemd не подходит вместо сервера.

До установки проверьте:

- Есть SSH-доступ с sudo и доступ к консоли провайдера на случай ошибки сети.
- Публичный IPv4 доступен клиентам; если используете домен, его DNS указывает
  на сервер. В мастер передаётся адрес без `https://`, пути и порта.
- Доступны репозитории ОС, Docker, PyPI, crates.io и GitHub. Это установка
  из исходников с загрузкой зависимостей, поэтому Интернет нужен и во время сборки.
- У провайдера разрешены Docker, TUN и сетевые модули ядра; для AmneziaWG
  нужен `/dev/net/tun`.
- Нет прежней установки Tunnel. Мастер отклоняет занятые каталоги и контейнеры;
  не удаляйте рабочие данные ради прохождения этой проверки.

## 2. Получите пакет

Нужны файл `.run` для выбранной ОС и соседний `.run.sha256` из доверенного
источника. Ссылки на опубликованный релиз здесь нет: пакет можно получить
у оператора или собрать из проверенной рабочей копии.

На компьютере разработчика нужен Python 3.12+ и Git, а также локальная копия
репозитория клиента с коммитом `4400ca12938619df92326c4abe21818bf39915e9`.
Из корня этого репозитория:

```sh
# Ubuntu 24.04
python3 scripts/build-installer.py --target ubuntu24 --client-source /путь/к/R-Trusttunnel

# CentOS Stream 9/10
python3 scripts/build-installer.py --target centos-stream --client-source /путь/к/R-Trusttunnel
```

Результат в `dist/`: `.run`, `.tar.gz` и отдельные `.sha256` для каждого файла.
`--output /путь/к/каталогу` меняет каталог результата. Сборщик включает текущие
исходники, в том числе незакоммиченные изменения; перед передачей проверьте
`git diff`. `manifest.json` внутри архива содержит HEAD сервера, SHA клиента
и хеши серверных файлов. Сборка не является полностью offline или побитово
воспроизводимой. Проверка SHA-256 обнаруживает повреждение файла, но требует
доверия к источнику самого файла контрольной суммы.

### Пакет с готовыми образами

Флаг `--with-images` один раз собирает образ портала с Rust codec для
`linux/amd64` и кладёт его в пакет вместе с `nginx:1.28-alpine`. Нужен Docker
с buildx; на ARM-машине нужна эмуляция amd64 и сборка идёт дольше. Вместо неё
можно собрать на x86-хосте с Docker по SSH: `DOCKER_HOST=ssh://<хост>` перед командой.

```sh
python3 scripts/build-installer.py --target ubuntu24 --with-images --client-source /путь/к/R-Trusttunnel
```

Результат — `tunnel-installer-<ОС>-amd64-images.run` и `.sha256`; запускается так же,
как обычный. Мастер проверяет SHA-256 архива образов по `manifest.json`, выполняет
`docker load` вместо сборки и отклоняет образы не под `linux/amd64`. На сервере
не нужны crates.io и Docker Hub для портала; репозитории ОС, Docker и (на CentOS)
PyPI по-прежнему нужны. Образы консоли и VPN-протоколов, как и раньше, собираются на сервере.

## 3. Запустите мастер на сервере

Перенесите `.run` и его `.sha256` в один каталог сервера. Для Ubuntu:

```sh
sha256sum -c tunnel-installer-ubuntu24-amd64.run.sha256
sudo bash tunnel-installer-ubuntu24-amd64.run
```

Для CentOS:

```sh
sha256sum -c tunnel-installer-centos-stream-amd64.run.sha256
sudo bash tunnel-installer-centos-stream-amd64.run
```

Продолжайте только после успешной проверки суммы. Введите публичный IPv4/домен
и e-mail администратора. Почта используется как логин; SMTP на этом этапе
не настраивается. Пароль мастер генерирует сам. При нестандартном SSH-порте
явно добавьте `--ssh-port 2222`, подставив свой порт.

Для запуска без диалога, например на Ubuntu:

```sh
sudo bash tunnel-installer-ubuntu24-amd64.run \
  --address vpn.example.com --email admin@example.com \
  --ssh-port 2222 --non-interactive
```

Мастер устанавливает зависимости и Docker, настраивает firewall, создаёт
самоподписанный TLS-сертификат на 365 дней, собирает портал и консоль, создаёт
администратора и проверяет HTTPS, вход и связь с агентом. Регистрация закрыта.
На CentOS SELinux сохраняется; особенности меток и модулей описаны
в [инструкции CentOS](fresh-install-centos.md).

Альтернатива `.run` — проверить сумму `.tar.gz`, распаковать его, перейти
в `tunnel-installer/` и выполнить `sudo bash deploy/install.sh`. Обычный Git
checkout без вложенного `client-source/` не заменяет собранный пакет.

## 4. Откройте консоль

На сервере после сообщения «Готово»:

```sh
sudo cat /opt/tunnel-installer/access.json
```

Сохраните логин, пароль и отпечаток сертификата в менеджер паролей.
Выполните команду из поля `ssh` **на своём компьютере** и оставьте её работать.
Если входите не как root, замените SSH-пользователя. Пример:

```sh
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:18443:127.0.0.1:18443 -p 2222 root@vpn.example.com
```

Откройте **https://localhost:18443/admin/login**, сверьте SHA-256 отпечаток
сертификата с `access.json`, затем разрешите самоподписанный сертификат
в браузере. После входа откроется единая консоль. При занятом локальном порте
используйте, например, `-L 127.0.0.1:19443:127.0.0.1:18443` и URL
`https://localhost:19443/admin/login`.

### Какие порты нужны

| Назначение | Порт сервера | Доступ |
|---|---|---|
| SSH | ваш TCP-порт | С компьютера администратора |
| HTTPS-панель | 18443/TCP | Только loopback, через SSH |
| Портал / консоль | 18082 / 18090 TCP | Только loopback |
| H UI после установки | 8081/TCP | Внешний доступ блокируется; вход через SSH |
| TrustTunnel | 8443/TCP и UDP | От VPN-клиентов после установки endpoint |
| Hysteria 2 | 443/UDP | После настройки ядра |
| AmneziaWG | 47443/UDP по умолчанию | После установки протокола |
| VLESS/CDN | выбранный TCP-порт origin | От CDN, настраивается отдельно |

Мастер разрешает SSH и стандартные VPN-порты в UFW/firewalld. При выборе другого
порта откройте его отдельно. Firewall хостинга настраивается у провайдера;
Docker может публиковать порты в обход части обычных правил firewall ОС.
Публичный HTTPS-вход на TCP 443 мастер не создаёт.

## 5. Установите протоколы и подключите клиента

В консоли откройте **«Протоколы» → «Проверить обновления» → «Установить»**.
Дождитесь успешного завершения задания в очереди, затем создайте пользователя
в разделе «Пользователи» и экспортируйте конфигурацию.

| Протокол | Что сделать после установки |
|---|---|
| TrustTunnel | Создать пользователя и ключ, скачать профиль с CA сервера |
| AmneziaWG 3.1 | Создать пользователя, импортировать `.conf` или QR в совместимый клиент 3.1 |
| Hysteria 2 | Настроить сертификат, ядро и выходы в H UI: установленное ядро остаётся выключенным |
| VLESS/CDN | Указать собственный домен и параметры CDN, открыть origin-порт, затем выдать `vless://`/QR |

H UI доступна через отдельный SSH-туннель на `127.0.0.1:8081`; пароль после
установки хранится в `/root/h-ui-bootstrap.json`. Пошаговые настройки:
[протоколы](protocols.md), [Hysteria](hysteria-server.md),
[клиенты](clients.md), [маршрутизация сервисов](service-routing.md).
Основной/резервный узлы, GeoIP, Telegram, SMTP, фильтры рекламы и подписанные
обновления клиентов настраиваются отдельно; свежая установка использует прямой выход.

## 6. Проверьте результат и сохраните данные

На сервере проверьте состояние без вывода секретов:

```sh
sudo docker compose -p trusttunnel-web -f /opt/trusttunnel-web/compose.yaml ps
sudo docker ps --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
sudo systemctl is-active vpn-console-agent
sudo journalctl -u vpn-console-agent -n 50 --no-pager
```

Проверьте вход в консоль, окончание задания установки и состояние нужного
протокола. Затем на отдельном устройстве импортируйте выданный профиль,
подключитесь и проверьте DNS, HTTPS и внешний IP. Отдельно проверьте блокировку
тестового пользователя. Маркер `/opt/tunnel-installer/complete` подтверждает
установку UI, а не подключение VPN с вашего устройства.

Сохраните согласованные базы, конфигурации и ключи по
[инструкции резервного копирования](operations.md#что-резервировать).
Сертификат самоподписанный, несмотря на путь `/etc/letsencrypt/live/АДРЕС/`;
автоматического ACME-продления мастер не настраивает. До истечения 365 дней
замените его, перезапустите использующие его компоненты и обновите CA клиентов
по [инструкции Ubuntu](fresh-install.md#что-требует-дополнительной-настройки).

## Если что-то пошло не так

| Симптом | Действие |
|---|---|
| Сбой DNS, загрузки или сборки | Устранить причину из вывода и повторить тот же `.run` с `--resume` |
| CentOS просит новое ядро | Выполнить `sudo reboot`, восстановить SSH и повторить `.run --resume` |
| Мастер сообщает о существующих каталогах | Выбрать сценарий для существующего сервера; для прерванной установки использовать `--resume` |
| Браузер не открывает панель | Проверить SSH-туннель, локальный порт и URL с `https://localhost:18443` |
| Панель работает, VPN не подключается | Проверить завершение задания протокола, его конфигурацию, порт и firewall провайдера |
| Ошибка установки протокола | Проверить очередь, `/opt/vpn-console/protocols/last-build.log` и `last-startup.log` на сервере |

`--resume` использует сохранённый `/opt/tunnel-installer/settings.json`;
не передавайте повторно `--address` и `--email`. После успешной установки
`--resume` только сообщает о её завершении. Установщик не откатывает пакеты ОС
и firewall автоматически. Не удаляйте каталог состояния для повторного старта.
Файлы доступа и журналы сборки не публикуйте без проверки на секреты.

## Границы проверки

Поддерживаются Ubuntu 24.04 и CentOS Stream 9/10 x86_64. Полный VM-прогон
Stream 9 не подтверждён. Изолированные проверки установки не заменяют
передачу трафика с реального устройства, проверку внешнего CDN и выходных узлов.
После каждого развёртывания выполните проверки из шага 6 на своей инфраструктуре.
