# Настройка клиентов

Используйте профиль, выданный вашим сервером. Он может доверять публичному
CA ([Let’s Encrypt](hysteria-letsencrypt.md)) или отдельному самоподписанному
сертификату; эти способы доверия требуют разных TLS-настроек.

## Что получить у администратора

Для Hysteria: адрес своего сервера (в примере `192.0.2.10`), UDP 443, connection password отдельного пользователя, salamander-пароль, публичный сертификат/его fingerprint. Для TrustTunnel: официальный `tt://?…`-профиль из панели или TOML с вложенным сертификатом. Эти данные передаются отдельно от Git.

## Linux: системный Hysteria через sing-box

Пример рассчитан на Linux с sing-box 1.14.2. Замените адрес сервера
и интерфейс в **обоих outbounds** на свои значения. Используйте [JSON-шаблон](../examples/sing-box-client.json).

1. Установите проверенный бинарник sing-box в `/usr/local/bin/sing-box` (`0755`).
2. Создайте `/etc/sing-box` и `/etc/hysteria`; установите выданный публичный сертификат в `/etc/hysteria/server.crt` (`0644`). Приватный серверный ключ клиенту не нужен.
3. Скопируйте шаблон в `/etc/sing-box/config.json`, подставьте два пароля. Файл root:root `0600`.
4. Проверьте конфигурацию, установите [unit](../examples/systemd/sing-box.service) и включите сервис:

```sh
sudo /usr/local/bin/sing-box check -c /etc/sing-box/config.json
sudo systemctl daemon-reload
sudo systemctl enable --now sing-box
ip -brief address show hy-tun
curl --noproxy '*' --max-time 20 https://api.ipify.org
```

Ожидаемый IP — адрес выбранного выхода. Проверяйте после появления TUN и завершения инициализации: запрос сразу после restart может уйти ещё через обычную сеть.

DNS использует FakeIP. Длинный список исключений `10.0.0.0/8` специально разложен на подсети так, чтобы **не исключать `10.254.77.1/32`**. Упрощение списка обратно до `10.0.0.0/8` сломает доступ к панелям. TCP 8081 и 18082 этого адреса явно направлены в Hysteria до правила private→direct.

`192.0.2.10/32` исключён из TUN для защиты от петли. Поэтому временный TrustTunnel-клиент может подключаться к тому же серверу напрямую. Приватные LAN/Docker сети обходят туннель.

Не запускайте одновременно два системных TUN. До включения нового клиента
остановите конкурирующий сервис и сохраните рабочую конфигурацию для отката.

## Временный native Hysteria-прокси для диагностики

[Шаблон native client](../examples/hysteria-client.json) использует публичный сертификат `/etc/hysteria/server.crt` и SOCKS на `127.0.0.1:18080`. Подставьте пароли в локальную копию, права `0600`, запустите `hysteria client -c /путь/к/client.json`. Такой клиент не содержит локальных domain-direct правил, поэтому удобен для проверки серверных исключений. Запрос: `curl --proxy socks5h://127.0.0.1:18080 https://api.ipify.org`. Он не меняет системные маршруты.

## Hysteria: Windows, macOS, Android, iOS

Выберите клиент с поддержкой **Hysteria 2**, salamander и проверки самоподписанного сертификата по CA/pin; список приложений меняется, используйте [официальный список](https://v2.hysteria.network/docs/getting-started/3rd-party-apps/). Hysteria 1 не совместима с этой конфигурацией.

Внесите параметры, перечисленные выше. TLS server name должен совпадать с DNS/IP SAN сертификата своего сервера. Включите VPN/TUN для всего устройства либо системный прокси для нужных приложений. На мобильной ОС подтвердите штатное разрешение создать VPN-профиль.

Серверные `.ru`/`.рф`/GeoIP-правила работают для трафика, дошедшего до сервера. Для **локального** обхода добавьте domain suffix `ru` и `xn--p1ai` в direct до общего правила proxy. Если клиент не умеет доменные правила, используйте поддерживаемые им IP-правила
и проверяйте фактический маршрут.

Для панелей направьте `10.254.77.1/32` через Hysteria, переопределив bypass LAN/private. Проверьте http://10.254.77.1:8081 и http://10.254.77.1:18082/admin . Если клиент не позволяет это исключение, используйте SSH-доступ с рабочего компьютера.

## TrustTunnel: официальный клиент

[Официальный проект](https://github.com/TrustTunnel/TrustTunnel) содержит ссылки на актуальные приложения и [CLI](https://github.com/TrustTunnel/TrustTunnelClient). Для Android/iOS используйте официальное приложение; на Windows/macOS/Linux доступность GUI зависит от текущего релиза, CLI — воспроизводимый вариант. Не импортируйте TrustTunnel в Hysteria-клиент.

В пользовательском кабинете получите профиль: `.toml` через «Скачать TOML» либо официальный `tt://?…`-deeplink. Передавайте ссылку целиком: в ней секрет и настройки TLS. Для новой учётной записи сначала создайте конфиг, чтобы endpoint получил её credentials.

Параметры: `192.0.2.10:8443`, hostname `trusttunnel.internal`, HTTP/2 либо HTTP/3. Это внутреннее имя сертификата, публичная DNS-запись для него не требуется — адрес endpoint задан явно. `skip_verification = false`, доверенный PEM вложен в профиль. Старый простой `tt://BASE64(user:password@host)` сторонней панели заменён официальным экспортёром.

CLI (профиль из панели включает TUN и меняет маршруты/DNS):

```sh
chmod 600 client.toml
sudo ./trusttunnel_client -c client.toml
```

Для безопасного параллельного теста замените весь раздел `[listener]` и `[listener.tun]` на:

```toml
[listener.socks]
address = "127.0.0.1:18090"
```

Запустите CLI без sudo и проверьте:

```sh
curl --proxy socks5h://127.0.0.1:18090 --max-time 20 https://api.ipify.org
```

Ожидается адрес выбранного выхода, а в прямом режиме — входного сервера. Для QUIC установите `upstream_protocol = "http3"`, для HTTP/2 — `"http2"`. Меняйте протокол в отдельной копии профиля. Не запускайте две копии на одном SOCKS-порту.

## Приёмка нового устройства

Проверьте внешний IP, DNS, HTTPS, Telegram, доступ к панелям и домашней LAN. После отключения VPN проверьте возврат сети. Звонки, IPv6 и длительные передачи проверяйте отдельно; успешное открытие сайта не подтверждает их автоматически.
