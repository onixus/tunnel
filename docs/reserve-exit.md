# Резервный выход Hysteria

Ниже пример независимого резервного выхода. Замените публичные адреса,
интерфейсы и подсети своими значениями. Переключение других VPN через консоль
описано в [маршрутизации сервисов](service-routing.md).

## Команды на сервере Hysteria

```sh
sudo /usr/local/sbin/hysteria-exit-switch status
sudo /usr/local/sbin/hysteria-exit-switch check
sudo /usr/local/sbin/hysteria-exit-switch reserve
sudo /usr/local/sbin/hysteria-exit-switch primary
```

`status` показывает выбранный в конфигурации выход. `check` выполняет реальный HTTPS-запрос через каждый SOCKS5 и сверяет внешний IP. `reserve` и `primary` переключают только последнее правило Hysteria `*(all)` между `reserve(all)` и `primary(all)`.

`.ru`, `.рф`, GeoIP СНГ, запрет private IP и доступ к панелям остаются прежними. TrustTunnel, системные default routes серверов и локальные исключения клиента не меняются.

**Это ручное переключение, не автоматический failover.** Выбор сохраняется в базе H UI и переживает restart/reboot. Переключение перезапускает H UI вместе с ядром Hysteria: текущие соединения прерываются, переподключение некоторых клиентов занимает десятки секунд. Если клиент не восстановился, перезапустите его VPN.

## Защита от неудачного переключения

1. До остановки панели скрипт проверяет целевой SOCKS5 и ожидаемый внешний IP.
2. Сохраняет прежний `HYSTERIA2_CONFIG` в `/root/hysteria-route-backups/*.yaml`, права `0600`.
3. Ставит независимый transient systemd-таймер отката на 180 секунд.
4. Останавливает H UI, читает актуальную конфигурацию и меняет catch-all и известные outbounds в SQLite.
5. Запускает H UI и временный native Hysteria-клиент без системного TUN. Через него проверяет реальный внешний IP.
6. При успехе снимает таймер; при ошибке восстанавливает прежнюю конфигурацию и запускает H UI. При аварийном завершении скрипта таймер делает восстановление позднее.

Проверки зависят от доступности `https://api.ipify.org`. Если сервис проверки недоступен, переключение не считается успешным. Принудительного обхода проверки нет. Probe использует `/etc/hysteria/client.json`: при ротации credentials используемой для probe учётной записи обновите и этот root-only файл. Пароли в аргументы процессов и stdout не передаются.

Не редактируйте настройки панели одновременно с переключением. После операции смотрите `status`, затем реальный клиентский запрос: сохранённая конфигурация и успешный клиентский трафик — разные проверки.

## Приватный туннель

| Узел | Интерфейс | IP | UDP |
|---|---|---|---|
| `192.0.2.10` | `wg-reserve` | `10.254.78.1/32` | 51831 |
| `203.0.113.10` | `wg-hysteria` | `10.254.78.2/32` | 51831 |

AllowedIPs — только противоположный /32, MTU 1380, PersistentKeepalive 25. Проверьте, что эта сеть не пересекается с основным туннелем и вашими
Docker/Amnezia/LAN-подсетями. Endpoint привязан к текущим публичным IP; изменение DuckDNS само по себе не обновляет сохранённые IP WG и ожидаемый адрес выхода.

На резерве установите `wireguard-tools`, совместимый sing-box и служебного
пользователя `hy-exit`. Настройте `wg-quick@wg-hysteria` и `hysteria-exit`.
SOCKS5 должен слушать приватный `10.254.78.2:1080`, требовать отдельный пароль
и отклонять приватные назначения. Укажите свой внешний интерфейс.

При использовании firewalld разрешите входной UDP 51831 только от входного
узла. В зоне интерфейса `wg-hysteria` добавьте узкие правила TCP 1080 и UDP relay
от `10.254.78.1` к `10.254.78.2`, проверьте runtime и permanent. На входном
сервере разрешите UDP 51831 только от резервного узла. Адреса в таблице — примеры.

## Файлы и восстановление

На входном сервере:

- `/usr/local/sbin/hysteria-exit-switch` — [исходник](../scripts/hysteria-exit-switch);
- `/etc/hysteria/exits.json` — root-only профили SOCKS, включая пароли и ожидаемые внешние IP;
- `/etc/wireguard/wg-reserve.conf`, `wg-reserve.key`;
- `/etc/systemd/system/h-ui.service.d/reserve.conf` — зависимость старта от WG;
- `/root/hysteria-route-backups/` — конфигурации для отката, содержат секреты.

На резерве:

- `/etc/wireguard/wg-hysteria.conf`, `wg-hysteria.key`;
- `/etc/hysteria-exit/config.json`, root:hy-exit `0640`;
- `/etc/systemd/system/hysteria-exit.service`;
- permanent rich rules firewalld.

Для новой установки повторите [межсерверную инструкцию](interserver.md), заменив адреса, порт, интерфейс и выбрав firewalld вместо nftables, если он используется на вашем выходном узле. У резервной службы зависимость должна быть `wg-quick@wg-hysteria`, а не `wg-private`. В `exits.json` задайте `primary` и `reserve`, каждый с полями `expected_ip` и `outbound` (Hysteria socks5 outbound). В основном профиле имя outbound `primary`, в резервном `reserve`. Пример структуры дан в [обезличенном шаблоне](../examples/hysteria-exits.json). Оба пароля должны совпадать с соответствующими SOCKS-серверами.

Сохраняйте эти файлы в защищённых backup. Не переносите их с секретами в Git. Скрипт предназначен для H UI 0.0.25 и текущей схемы SQLite; после обновления панели проверьте совместимость.

## Проверка

`wg show wg-reserve` на входе и `wg show wg-hysteria` на резерве должны
показывать handshake. Затем проверьте оба SOCKS-выхода, переключение, фактический
IP, TCP/HTTPS, UDP DNS и сохранение исключений с отдельного клиента.
Проверьте откат при контролируемой ошибке в окно обслуживания. Один ping
не подтверждает и не опровергает работоспособность SOCKS5.
