# Резервный выход Hysteria

Добавлен 28.09.2026. Основной выход — `onixus.ru` (`151.241.234.124`), резервный — `onixus-reverse.duckdns.org` (`185.199.158.8`). После приёмки выбран основной.

## Команды на сервере Hysteria

```sh
sudo /usr/local/sbin/hysteria-exit-switch status
sudo /usr/local/sbin/hysteria-exit-switch check
sudo /usr/local/sbin/hysteria-exit-switch reserve
sudo /usr/local/sbin/hysteria-exit-switch primary
```

`status` показывает выбранный в конфигурации выход. `check` выполняет реальный HTTPS-запрос через каждый SOCKS5 и сверяет внешний IP. `reserve` и `primary` переключают только последнее правило Hysteria `*(all)` между `reserve(all)` и `onixus(all)`.

`.ru`, `.рф`, GeoIP СНГ, запрет private IP и доступ к панелям остаются прежними. TrustTunnel, системные default routes серверов и локальные исключения клиента не меняются.

**Это ручное переключение, не автоматический failover.** Выбор сохраняется в базе H UI и переживает restart/reboot. Переключение перезапускает H UI вместе с ядром Hysteria: текущие соединения прерываются, переподключение некоторых клиентов занимает десятки секунд. При тесте первый запрос `.120` после restart завершился timeout; последующие запросы успешно прошли через резерв. Если клиент не восстановился, перезапустите его VPN.

## Защита от неудачного переключения

1. До остановки панели скрипт проверяет целевой SOCKS5 и ожидаемый внешний IP.
2. Сохраняет прежний `HYSTERIA2_CONFIG` в `/root/hysteria-route-backups/*.yaml`, права `0600`.
3. Ставит независимый transient systemd-таймер отката на 180 секунд.
4. Останавливает H UI, читает актуальную конфигурацию и меняет catch-all и известные outbounds в SQLite.
5. Запускает H UI и временный native Hysteria-клиент без системного TUN. Через него проверяет реальный внешний IP.
6. При успехе снимает таймер; при ошибке восстанавливает прежнюю конфигурацию и запускает H UI. При аварийном завершении скрипта таймер делает восстановление позднее.

Проверки зависят от доступности `https://api.ipify.org`. Если сервис проверки недоступен, переключение не считается успешным. Принудительного обхода проверки нет. Probe использует `/etc/hysteria/client.json`: при ротации учётной записи `existing-clients` обновите и этот root-only файл. Пароли в аргументы процессов и stdout не передаются.

Не редактируйте настройки панели одновременно с переключением. После операции смотрите `status`, затем реальный клиентский запрос: сохранённая конфигурация и успешный клиентский трафик — разные проверки.

## Приватный туннель

| Узел | Интерфейс | IP | UDP |
|---|---|---|---|
| `139.100.233.173` | `wg-reserve` | `10.254.78.1/32` | 51831 |
| `185.199.158.8` | `wg-hysteria` | `10.254.78.2/32` | 51831 |

AllowedIPs — только противоположный /32, MTU 1380, PersistentKeepalive 25. Отдельная сеть не пересекается с основным `10.254.77.0` и существующими Docker/Amnezia-сетями резерва. Endpoint привязан к текущим публичным IP; изменение DuckDNS само по себе не обновляет сохранённые IP WG и ожидаемый адрес выхода.

На резервном CentOS Stream 9 установлен пакет `wireguard-tools`, официальный sing-box 1.14.2 и пользователь `hy-exit`. Службы `wg-quick@wg-hysteria` и `hysteria-exit` включены в автозапуск. SOCKS5 слушает `10.254.78.2:1080`, требует отдельный пароль, отклоняет приватные назначения и выходит IPv4 через `ens192`.

Firewalld: входной UDP 51831 разрешён только от `139.100.233.173`. На интерфейсе `wg-hysteria` в зоне `public` добавлены узкие rich rules для TCP 1080 и UDP relay от `10.254.78.1` к `10.254.78.2`; настройки внесены runtime и permanent без полной перезагрузки firewall. Остальные сервисы, Docker и Amnezia не перенастраивались. На входном сервере UFW разрешает UDP 51831 только от `185.199.158.8`.

## Файлы и восстановление

На входном сервере:

- `/usr/local/sbin/hysteria-exit-switch` — [исходник](../scripts/hysteria-exit-switch);
- `/etc/hysteria/exits.json` — root-only профили SOCKS, включая пароли и ожидаемые внешние IP;
- `/etc/wireguard/wg-reserve.conf`, `wg-reserve.key`;
- `/etc/systemd/system/h-ui.service.d/reserve.conf` — зависимость старта от WG;
- `/root/hysteria-route-backups/` — конфигурации для отката, содержат секреты.

На резерве:

- `/etc/wireguard/wg-hysteria.conf`, `wg-hysteria.key`;
- `/etc/hysteria-exit/config.json`, root:hy-exit `0640`;
- `/etc/systemd/system/hysteria-exit.service`;
- permanent rich rules firewalld.

Для новой установки повторите [межсерверную инструкцию](interserver.md), заменив адреса, порт, интерфейс и выбрав firewalld вместо nftables-правил onixus.ru. У резервной службы зависимость должна быть `wg-quick@wg-hysteria`, а не `wg-private`. В `exits.json` задайте `primary` и `reserve`, каждый с полями `expected_ip` и `outbound` (Hysteria socks5 outbound). В основном профиле имя outbound `onixus`, в резервном `reserve`. Пример структуры дан в [обезличенном шаблоне](../examples/hysteria-exits.json). Оба пароля должны совпадать с соответствующими SOCKS-серверами.

Сохраняйте эти файлы в защищённых backup. Не переносите их с секретами в Git. Скрипт предназначен для H UI 0.0.25 и текущей схемы SQLite; после обновления панели проверьте совместимость.

## Проверка

`wg show wg-reserve` на входе и `wg show wg-hysteria` на резерве должны показывать handshake. ICMP echo в проведённой проверке не ответил; не используйте один ping как доказательство отказа туннеля — аутентифицированные TCP/UDP через него проверены успешно.

Подтверждены: проверка обоих SOCKS-выходов, переключение Hysteria на IP `185.199.158.8`, TCP/HTTPS с `.120`, UDP DNS к 1.1.1.1 и 77.88.8.8, сохранение исключений. Контролируемая ошибка послепереключательной проверки использована для проверки восстановления старой конфигурации. Затем выполнен возврат на основной выход.
