# Единая VPN-панель

Развёрнута 1 октября 2026 на **https://onixus-rf.duckdns.org/console/**.
Вход — существующая учётная запись администратора TrustTunnel.
После входа `/admin/dashboard` перенаправляет в новую панель.

Доступны:

- Общий обзор Hysteria, TrustTunnel, устройств R-TrustTunnel и выходных узлов.
- Пользователи обоих VPN: создание, блокировка/разблокировка; пароль кабинета
  TrustTunnel; срок, квота и число устройств Hysteria.
- Выпуск, экспорт, ротация и отзыв ключей; отзыв регистрации устройства с его
  привязанными ключами. Секреты не включаются в общий список или журнал.
- Основной/резервный выход Hysteria и упорядоченные исключения по доменам,
  подсетям и GeoIP. Проверка обоих выходов, ревизии конфигурации и откат при
  неуспешной проверке применённого маршрута.
- Каталог подписанных Windows-релизов R-TrustTunnel и публикация канала после
  проверки подписи, срока и полного хеша установщика. Ссылка на Linux Flatpak.
- Установка предварительно подготовленных оператором серверных пакетов.
  Произвольная загрузка бинарников из UI не разрешена. Для TrustTunnel необходим
  установленный на сервере протокольный probe; пока он не настроен, обновление
  этого компонента блокируется до изменения контейнера.
- Контакты с согласием на уведомления, черновики e-mail/Telegram-рассылок,
  отдельное подтверждение отправки, статусы каждого адресата.
- Существующий приватный Telegram-бот, очередь задач и журнал администратора.

## Снимок маршрутизации при приёмке 1 октября 2026

Hysteria выбирает выход на уровне своего приложения. На момент проверки выбран
`reserve`. Основной выход проверен реальным запросом: `212.237.219.42`; резервный:
`185.199.158.8`. Адреса могут меняться; панель показывает имена из действующих
профилей, а кнопка проверки получает фактический egress.

**TrustTunnel и трафик самого onixus-rf по-прежнему выходят напрямую.** Редактор
Hysteria не меняет их маршрутизацию. Общие правила для всех протоколов, системное
policy routing и автоматический failover в этой поставке не реализованы.

## Приёмка

- 15 изолированных тестов консоли: авторизация, CSRF/Origin, отсутствие секретов
  в snapshot, идемпотентность, восстановление jobs без повторного исполнения,
  удалённый администратор, согласие на рассылки, экспорт, отзыв устройства,
  ограничения операций, подпись/хеш/защита от downgrade, валидация правил,
  конфликт ревизий и откат при ошибке протокольной проверки.
- 7 существующих тестов обмена профилями с настоящим Rust-кодеком проходят.
- Браузер: все восемь разделов открываются; нет ошибок JavaScript. Проверен
  адаптивный обзор при ширине 390 px. Авторизованный UI проверялся с синтетическими
  данными на локальном стенде; публичная страница входа — через настоящий HTTPS.
- Публичный HTTPS API с существующей admin-идентичностью возвращает живые данные;
  неавторизованный API даёт 401, mutation без CSRF — 403. Секретов в snapshot нет.
- Живой H UI: временный пользователь создан, заблокирован, разблокирован;
  ключ сменён и экспортирован; отдельно проверено изменение срока и лимитов.
  Временные записи удалены после проверки.
- Реальная очередь выполнила проверку обоих выходов; повторный request ID не
  создал вторую задачу. Успешная задача сохранилась после рестарта sidecar.
- TrustTunnel HTTP lifecycle пройден в отдельном контейнере с tmpfs `/data`,
  без внешней сети и без боевых mount: создание, пароль, блокировка/разблокировка,
  выпуск/ротация/отзыв ключа, отзыв устройства, экспорт реальным Rust-кодеком.
- Развёртывание не перезапускало работающие Hysteria и TrustTunnel. Боевые
  маршруты, credentials и канал обновлений оставлены без изменений.

Не выполнялись на бою: переключение маршрута, установка серверного обновления,
переключение канала Windows, отправка реальных писем/Telegram-сообщений.
Их реализация не означает, что эти действия уже были выполнены и проверены на
боевых пользователях. Обновления серверов откатываются при перехваченной ошибке;
после аварийного выключения хоста во время установки требуется ручное восстановление.

## Развёртывание и откат

Образ на момент приёмки: `vpn-console:20261001-144841`.
Исходники на сервере: `/opt/rtrust-releases/20261001-console`.
Данные/агент: `/opt/vpn-console`; unit `vpn-console-agent.service`.
Новый контейнер `vpn-console`, публичный доступ через существующий nginx.

Backup последнего развёртывания при приёмке: `/opt/vpn-console/backups/20261001-144841`.
В нём SQLite snapshot, ключ шифрования профилей, nginx и предыдущие файлы агента.
Предыдущий рабочий контейнер сохранён остановленным как
`vpn-console-backup-20261001-144841`.

Для отката **версии консоли** используйте backup `20261001-144841`: верните
предыдущие файлы агента/unit и сохранённый контейнер под именем `vpn-console`.
Сохраните текущий каталог `/opt/vpn-console/data`; предыдущий образ читает его.
Перезапустите агент, проверьте `/console/healthz` и вход администратора.

Для возврата **к старой админке без консоли** используйте nginx из backup
`/opt/vpn-console/backups/20261001-144052/nginx.conf`, снятого до первого успешного
включения `/console/`. Конфигурация nginx из более позднего backup уже содержит
консоль и не вернёт старую админку. Сначала сохраните текущий конфиг, затем замените
`/opt/rtrust-releases/20260930-portal/portal-nginx.conf`, выполните `nginx -t` и reload
в контейнере `rtrust-portal-https`. После проверки входа в старую админку остановите
только `vpn-console` и `vpn-console-agent.service`; VPN-службы не трогайте.
Не заменять текущую БД старой копией поверх новых изменений пользователей.

Подробные границы доверия, форматы пакетов, ограничения доставки и команды
проверки описаны в [server/console/README.md](../server/console/README.md).

- [Локальные фильтры рекламы и трекеров](local-adblock.md) — ежедневное обновление из нескольких источников, усиление RU/SU и состояние в консоли.
