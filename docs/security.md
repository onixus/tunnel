# Секреты и ограничения безопасности

Репозиторий не является хранилищем VPN-паролей или личной топологии.
В документации используйте домены `example.com`, адреса документационных сетей
и синтетические учётные записи. Скриншоты тоже должны содержать вымышленные
имена узлов и адреса. Рабочие IP, контакты, локальные пути и журнал
конкретного развёртывания храните отдельно. Ключи и секреты в шаблонах
заменяются маркерами `REPLACE_LOCALLY_*`.

## Что хранить отдельно

- SSH private keys и их passphrase;
- WireGuard PrivateKey;
- пароли UI, JWT/SECRET_KEY, базы SQLite и их backups;
- Hysteria connection password, salamander password, SOCKS password;
- TrustTunnel credentials, `client.toml`, `tt://?…`-ссылки и QR;
- приватные TLS-ключи.

Клиенту передаётся публичный TLS-сертификат/пин, **не private key**. Перед передачей публичного сертификата сверяйте fingerprint по доверенному каналу. Для новых установок создавайте отдельные пароли через `openssl rand -hex 16` или криптографический генератор.

На серверах конфигурации с секретами должны иметь `0600` либо `0640` с единственной служебной группой; каталоги `0700/0750`. Ограничьте доступ к резервным копиям. `.gitignore` — страховка от ошибок, а не замена проверки staged diff.

## Ограничения при развёртывании

- Используйте SSH по ключам; ограничьте административные панели loopback/SSH
  или HTTPS с авторизацией. Для публичного входа настройте защиту отдельно.
- H UI — непривилегированный пользователь и systemd hardening; только bind privileged ports.
- Межсерверный WG — /32 peer routes и фильтрация по адресам.
- SOCKS5 — private bind, пароль, запрет приватных назначений.
- TrustTunnel-контейнер — UID 10001, drop ALL capabilities, no-new-privileges, read-only rootfs, без Docker socket.
- TrustTunnel portal — случайные отдельные пароли, отключённая регистрация, ограниченный срок JWT.
- Проверка TLS остаётся включённой.

UFW не контролирует все Docker DNAT-публикации. Панель TrustTunnel защищена **loopback publish** `127.0.0.1:18082:8000`; не заменяйте его на `18082:8000`. VPN endpoint публикует 8443 TCP/UDP; nginx новой установки слушает loopback 18443; публичный TCP 443 настраивается отдельно. [Fail2ban веб-входа](web-protection.md) фильтрует до Docker DNAT.

## Известные ограничения

Панели сторонние, полного аудита не было. Доступ через VPN даёт достижимость страницы входа всем авторизованным VPN-клиентам; административный пароль всё равно обязателен. Не считайте VPN-учётку разрешением на администрирование.

Самоподписанные сертификаты требуют управления доверием и сроками. Мастер не настраивает автопродление и автоматическое обновление GeoIP. Экспорт H UI требует отдельного добавления доверия к сертификату. У TrustTunnel экспорт исправлен локальным patch.

IPv4 — проверенный выходной режим. Kill switch не заявлен. Остановка клиентского TUN может вернуть прямой интернет. Ни один из этих протоколов не гарантирует обход любого DPI; оценивайте по фактическому подключению из нужной сети.

При утечке секрета: отзовите соответствующего пользователя/ключ, выдайте новый профиль и только затем удаляйте следы из репозитория. Переписывание истории не отменяет утечку.

## Граница доверия единой консоли

Администраторы TrustTunnel получают управление VPN-протоколами через консоль.
Отдельный RBAC и независимый identity provider не добавлены. Non-root sidecar
обращается к root-агенту через Unix socket с группой 10001; не выдавайте эту группу
посторонним процессам. Агент принимает только фиксированные операции.

CSRF/Origin проверяются для изменений; секреты не включаются в snapshot или
очередь задач. Раскрытие VPN-ключа — отдельная операция. Telegram-токен хранится
на сервере. Рассылки требуют согласия, черновика и подтверждения; неоднозначная
доставка не повторяется автоматически. [Подробная модель](../server/console/README.md).
