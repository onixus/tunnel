# Локальная блокировка рекламы и трекеров

Развёрнута на onixus-rf 1 октября 2026. Решение о блокировке принимается
**на сервере**, по локальным файлам. Публичный AdGuard DNS не используется.
Для незаблокированных имён сохранены прежние DNS сервера хостинга
`188.93.16.19` и `188.93.17.19`; это не рекурсивный DNS от корневых серверов.
DNS query log, статистика запросов и облачные проверки Safe Browsing выключены.

## Источники и усиление RU/SU

[Политика](../deploy/adblock/policy.json) объединяет:

- [HaGeZi Pro](https://github.com/hagezi/dns-blocklists): основной список доменов.
- [AdGuard DNS Filter](https://github.com/AdguardTeam/AdGuardSDNSFilter): локальные DNS-совместимые правила, не DNS-сервис.
- [StevenBlack hosts](https://github.com/StevenBlack/hosts): дополнительный независимый источник.
- HaGeZi Ultimate: более агрессивная выборка **только доменов `.ru` и `.su`**.
- Локальные правила российских рекламных сетей и счётчиков: AdFox,
  рекламные/аналитические поддомены Яндекса, VK/Mail, Yadro и TNS.

Первый рабочий набор: 388 409 доменов, включая 4 704 `.ru`/`.su`.
Количество меняется при обновлении. Зоны целиком не блокируются. Корни
`yandex.ru`, `mail.ru`, `vk.com` и инфраструктурные имена защищены от блокировки
целиком; рекламные поддомены могут блокироваться. Это намеренно строгая политика:
при ложном срабатывании оператор добавляет домен в `allow` файла
`/opt/vpn-adblock/policy.json`, затем запускает обновление из консоли.

Парсер не превращает правила для отдельных URL, типов ресурсов, third-party
контекста или косметические правила в блокировку всего сайта. Поддерживаются
только проверенные домены, hosts и безусловные `||domain^`/`@@||domain^`.
Списки скачиваются на сервер; их содержимое не включено в Git, лицензии остаются
у соответствующих источников.

## Путь трафика

Локальный AdGuard Home v0.107.79 закреплён digest образа. Производный образ
снимает файловую capability и запускается UID 10001, с `cap-drop ALL`, read-only
rootfs и `no-new-privileges`. Конфигурация/кэш — отдельные volumes.

- DNS контейнера: `172.18.0.53:53` в существующей закрытой Docker-сети.
- На хосте DNS опубликован только на `127.0.0.1:53` TCP/UDP.
- Служебный API опубликован только на `127.0.0.1:3001`; случайный пароль
  находится в root-only `/opt/vpn-adblock/api.json`. Админка не проксируется наружу.
- Hysteria использует локальный DNS; sniffing HTTP/TLS/QUIC позволяет учитывать
  имя в поддерживаемых соединениях. Правила DNS выполняются до выбора выхода.
  Для UDP-пакетов добавлен NAT только для UID службы `hysteria`.
- TrustTunnel использует локальный DNS для разрешения имён. Обычный DNS TCP/UDP
  внутри Docker-сети перенаправляется к локальному фильтру. Контейнер фильтра
  исключён из перехвата, чтобы не создавать рекурсию. SNAT обеспечивает обратный
  путь ответа через conntrack при перенаправлении в ту же Docker-сеть.
- Таблица `ip vpn_adblock_dns` отдельная: существующие правила UFW/Docker/SSH
  и fail2ban не заменяются. Публичных DNS/DoH listeners не добавлено.

Стандартные клиентские профили и их DNS defaults сохранены. Собственный внешний
DoH/DoT/DoQ приложения или клиента, DNS вне VPN и клиентские direct-исключения
могут обходить эту фильтрацию. Особенно проверьте клиентов с прямым обходом всей
зоны `.ru`: трафик, который не дошёл до сервера, сервер фильтровать не может.
Для локальных списков отключите внешний зашифрованный DNS override в профиле.
DNS-блокировка не удаляет рекламу с того же домена, что полезный контент, и не
заменяет браузерный косметический фильтр. IPv6 data plane здесь не заявлен.

## Ежедневное обновление и панель

`vpn-adblock-update.timer` запускает обновление каждый день в 03:15 по времени
сервера (UTC), плюс случайная задержка до 15 минут; `Persistent=true` догоняет
пропущенный запуск. Обновления не перезапускают VPN или DNS-контейнер:
новый набор загружается через служебный API.

Все источники обязаны пройти загрузку HTTPS без redirect, проверку размера,
синтаксиса и количества. Падение более чем на 40% или рост более чем вдвое по
одному источнику останавливает публикацию. При ошибке остаётся предыдущий набор.
Новая версия публикуется атомарной ссылкой; после hot reload проверяется
уникальное контрольное правило поколения. При ошибке применения ссылка и
фильтры откатываются. Хранятся текущее и предыдущее поколения.

В консоли **Маршрутизация → Локальная фильтрация рекламы** доступны состояние,
количество доменов, источники, последний успех/ошибка, следующий запуск и
кнопка обновления. Кнопка запускает systemd service; завершение отображается
в состоянии фильтра, отдельно от факта постановки задания в очередь.
Применение маршрутов сохраняет защищённые правила DNS.

```sh
systemctl status vpn-adblock-update.timer vpn-adblock-dns.service
systemctl start vpn-adblock-update.service
journalctl -u vpn-adblock-update.service --since yesterday
```

## Установка и откат

На ingress из копии этого репозитория, root, с существующими Docker-сетью,
TrustTunnel, H UI и агентом консоли:

```sh
python3 deploy/install-local-resolver.py
python3 deploy/install-adblock.py
python3 deploy/install-console.py
```

Установщик рассчитан на текущую сеть `172.18.0.0/16`, gateway `.1` и свободный
адрес `.53`, и проверяет эти предпосылки. Сначала поднимается отдельный resolver
и проверяется фильтрация, потом изменяются VPN. Во время первой интеграции
возможны краткие переподключения; повторное применение той же конфигурации не
перезапускает VPN без необходимости. Переключение маршрута имеет прежний watchdog.

До интеграции сохраняются compose, конфигурация H UI и прежние правила DNS
в `/opt/vpn-console/backups/adblock-<timestamp>`. Для полного отката восстановите
compose и H UI из выбранной копии, примените compose и перезапустите H UI;
остановите `vpn-adblock-update.timer` и `vpn-adblock-dns.service`. Затем можно
остановить `vpn-adblock`. Не останавливайте resolver, пока VPN всё ещё использует
его адрес. Не сбрасывайте firewall целиком. Первичная дофильтровая копия этой
установки: `adblock-20261001-154408`; последующие копии могут уже содержать фильтр.

## Проверки

- Семь тестов парсера, защиты имён и отката неуспешного применения.
- 15 тестов консоли, включая сохранение DNS-правил при изменении маршрутов;
  четыре теста Telegram. Изолированный контейнер: реальные операции портала
  и экспорт Rust-профиля, без подключения production DB или отправки сообщений.
- Боевой resolver блокирует DoubleClick, `mc.yandex.ru` и домен из `.su`;
  `example.com` и корень `yandex.ru` разрешаются.
- Hysteria: разрешённый HTTPS через резервный выход, блокировка доменов и
  UDP DNS через VPN. TrustTunnel native: HTTPS и блокировка трекера по HTTP/2
  и HTTP/3. Rust engine: HTTPS, блокировка трекера и перенаправленный TCP DNS
  по обоим транспортам; использован синтетический `.invalid` запрос в сторону
  принадлежащего пользователю резервного узла, ответ получен локально.
- Проверено ручное исполнение того же ежедневного service: успешная смена
  поколения и отсутствие ошибки. Следующий запуск назначен timer.

## Защита записи поколений, 2 октября 2026

Опубликованные поколения списков неизменяемы. При неизменном содержимом
обновление сверяет существующий файл и использует его повторно без перезаписи.
Новый набор записывается во временный каталог на той же файловой системе,
синхронизируется и переименовывается перед переключением `current`.
Ошибка записи удаляет временный каталог и сохраняет текущий список целиком.
Обнаруженное повреждение существующего поколения останавливает обновление.

Изолированные тесты моделируют частичную запись и нехватку места как для нового,
так и для неизменного набора. Это проверка кода; наличие исправления в рабочем
обновляющем скрипте на сервере нужно проверять после развёртывания.
