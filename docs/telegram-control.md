# Telegram-управление

Отдельный бот запускается через `vpn-telegram.service`. Код:
[vpn-telegram.py](../scripts/vpn-telegram.py),
[unit](../examples/systemd/vpn-telegram.service).
Создайте собственного бота и задайте его token, ID владельца и chat ID
в `/etc/vpn-telegram/config.json`, root `0600`. Настройте адрес панели и
зависимости по своей топологии. Один token должен иметь только один polling-процесс;
при переходе с бота H UI отключите его polling до запуска отдельной службы.

## Команды

- `/status`: службы, ресурсы, выход и сертификат.
- `/panel` и `/panels`: ссылка настроенной HTTPS-консоли.
- `/bans`: состояния jail `sshd` и `vpn-web`.
- `/route`: ручной выбор выхода Hysteria.
- `/restart`: перезапуск поддерживаемого VPN.
- `/help`: справка.

Проверяются sender ID, chat ID и тип private. Управление разрешено владельцу.
Изменения требуют одноразового подтверждения с TTL; устаревшие команды
и повторные callback отклоняются. Произвольные shell-команды не принимаются.
Offset сохраняется до исполнения: после сбоя проверьте состояние и при
необходимости повторите команду. Сервис управляет Docker/systemd от root,
поэтому защищайте token и аккаунт владельца.

## Обслуживание

```sh
systemctl status vpn-telegram
journalctl -u vpn-telegram --since '10 minutes ago'
```

Остановить: `systemctl disable --now vpn-telegram`.
При возврате к встроенному боту H UI сначала остановите отдельный сервис.
Не запускайте два обработчика одного token одновременно.

## Консоль и получатели

Консоль показывает состояние бота и позволяет готовить рассылки получателям
с согласием. Новый polling-процесс не создаётся, token в браузер не передаётся.
Адресат должен открыть своего бота и отправить `/start` или `/id`. Постороннему
пользователю бот возвращает только его собственный ID, с ограничением частоты;
управляющие команды остаются доступны владельцу.
[Доставка](../server/console/README.md#delivery-and-telegram).

Панель должна быть доступна с устройства пользователя по настроенному адресу.
Для диагностики предпочтителен [SSH-туннель](panels.md). Если разрешаете доступ
из VPN-контейнера к панели хоста, определите фактические bridge, подсеть и адрес,
добавьте только нужный порт в firewall и проверьте внешний запрет отдельно.
Не копируйте ID Docker-моста с другого сервера и не открывайте все private-сети.

Тесты: [test-vpn-telegram.py](../tests/test-vpn-telegram.py).
Защита HTTPS-входа описана [отдельно](web-protection.md).
